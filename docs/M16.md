# M16 « En ligne » — contrat partagé (v1.1.0)

Propriétaire : Orchestrateur. Décisions D-230 à D-235.

## 1. Objectifs

- **Sauvegardes dans le cloud** (facultatives) : emplacements de partie (v6 : `current.json`, `meta.json`, instantanés `day_NN.json`) et profil global, synchronisés entre PC, Steam Deck et version Web. **Hors ligne d'abord** : le jeu reste entièrement jouable sans compte ni réseau.
- **Classement de la Garde de nuit** : graine du jour (et codes libres), meilleur score par joueur et par graine.
- **Statistiques des fins** : pourcentage de joueurs ayant obtenu chaque fin, affiché dans le Dossier **seulement pour les fins déjà vues** (aucun spoiler).

## 2. Serveur : PocketBase sur Coolify (D-230)

- Dossier **`server/`** : `Dockerfile` (image officielle PocketBase, version figée), `pb_migrations/` (collections et règles d'accès en JS, versionnées), `pb_hooks/` (validation, agrégats), `README.md` (déploiement Coolify, volume persistant `/pb/pb_data`, sauvegardes, variables).
- Domaine prévu : **`https://api.clearance.cardormedia.com`** (CORS ouvert aux origines du site et à `null`/natif ; le client natif n'envoie pas d'Origin). Le domaine est une variable du client (`Settings`/constante surchargeable) ; le jeu fonctionne s'il est injoignable.
- **Authentification** (D-231) : compte **sans mot de passe** par **code à usage unique envoyé par e-mail** (OTP PocketBase), utilisable sur Steam Deck sans navigateur ; pseudo public facultatif (sinon « Agent·e #xxxx ») ; suppression du compte et de toutes ses données depuis le jeu (RGPD) ; jeton rafraîchi et stocké localement (jamais l'e-mail en clair dans les journaux).
- **Collections** (règles : un joueur ne lit et n'écrit que ses propres lignes, sauf classement/agrégats en lecture publique) :
  - `saves` : `user` (relation), `slot` (1–3, 0 = profil), `kind` (`current`/`meta`/`snapshot`/`profile`), `day` (pour les instantanés), `payload` (JSON, ≤ 256 Ko), `game_version`, `save_serial`, `saved_unix_ms`, `device` (libellé court), unicité (`user`,`slot`,`kind`,`day`).
  - `garde_scores` : `user`, `seed_code` (ex. `NUIT-2026-11-01` ou code libre), `garde_version`, `score`, `errors`, `tier_max`, `duration_s`, `first_try` (bool), `game_version`, `created` ; un meilleur score par (`user`,`seed_code`,`garde_version`) ; **vérifications serveur** de plausibilité (score ≤ borne liée à la durée et au nombre de passagers, erreurs ≤ 3, limite de fréquence par utilisateur) — le classement est **amical**, sans anti-triche cryptographique (D-233).
  - `ending_events` : `user`, `ending_id`, `variant`, `act`, `difficulty`, `game_version` ; un événement par (`user`,`ending_id`,`variant`) ; **agrégats publics** exposés par une route `/api/clearance/endings` (pourcentages par fin, par rapport au nombre de joueurs ayant terminé au moins une partie ; mise en cache).
  - Route `/api/clearance/leaderboard?seed=…&limit=…` (top N + rang du joueur connecté).
- Données minimales : pas de télémétrie au-delà de ces trois collections ; politique de confidentialité courte dans `server/README.md` et sur le site.

## 3. Client Godot (D-232)

- Service **`OnlineService`** (autoload ou service, au choix de l'Architecte, documenté) : état (déconnecté / connexion / connecté / hors ligne / erreur), connexion OTP (demande du code, saisie du code), déconnexion, suppression du compte, pseudo.
- **Synchronisation des sauvegardes** :
  - quand : à l'écran titre (tirage), après chaque sauvegarde du soir et à la fin d'une partie (envoi), à la demande (« Synchroniser maintenant ») ;
  - par emplacement, comparaison `save_serial` puis `saved_unix_ms` ; **jamais de perte silencieuse** : en cas de divergence réelle (deux appareils ont avancé), la version distante perdante est gardée en copie locale (`slot_N/conflict_<horodatage>/`) et l'écran Charger le signale avec un choix « Garder celle-ci / l'autre » ;
  - le profil (fins vues, portraits, records, épilogues) est **fusionné** (union) plutôt qu'écrasé ;
  - la démo et le jeu complet ne partagent pas leurs emplacements (la démo synchronise ses propres données sous un `kind` préfixé `demo_` ou ne synchronise pas : choix de l'Architecte, documenté).
- **Classement** : envoi du score de Garde à la fin d'une garde (si connecté), écran de fin de garde et accueil de la Garde affichent le top 10 de la graine du jour et le rang du joueur ; hors ligne : records locaux comme aujourd'hui.
- **Statistiques des fins** : envoi de l'événement à l'obtention d'une fin (si connecté) ; Dossier › Fins affiche « X % des agents » **uniquement pour les fins vues** ; cache local.
- **Interface** : Options › Compte (connexion, pseudo, synchronisation automatique on/off, synchroniser maintenant, déconnexion, supprimer le compte et les données), indicateur discret d'état au titre ; tout en FR/EN (clés en fin de `fr.csv`/`en.csv`), manette et accessibilité (UI_FLOW §9).
- **Réseau** : `HTTPRequest`, délais courts, nouvelles tentatives espacées, aucune requête bloquante sur le fil principal pendant un shift ; Web : même code (fetch), le domaine de l'API doit renvoyer les en-têtes CORS et `Cross-Origin-Resource-Policy: cross-origin` (la page `/play/` est en COEP `require-corp`).
- Les tests GUT n'utilisent **jamais** le réseau réel : faux serveur local (petit serveur HTTP de test ou double du service) ; un test d'intégration optionnel contre un PocketBase local lancé par un outil.

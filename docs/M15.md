## 2. Localisation (D-213, D-214)

- Langues : **français** (source, `fr.csv`) et **anglais** (`en.csv`, fichier séparé, mêmes clés, en-tête `keys,en`). Toute clé ajoutée en FR doit exister en EN (test GUT).
- Réglage `language` (`fr` / `en`, défaut = langue du système si `en*`, sinon `fr`), appliqué à chaud (`TranslationServer.set_locale` + signal `settings_changed` → les écrans se re-traduisent ou se reconstruisent).
- **Ce qui n'est pas traduit** : noms propres (personnages, lieux, Halcyon Gate), langue **tessar** (inventée), codes (N° ID, MRZ, codes employeurs), sigles de règles (R01…). Les anomalies restent identiques dans les deux langues (même CaseKey) : la traduction ne touche jamais la logique.
- Les documents en jeu restent dans la langue de la station (FR) **ou** sont traduits ? → **traduits** (lisibilité) ; les valeurs de champ générées (noms, origines codées, dates) suivent un format neutre `JJ.MM.AAAA`.
- Pseudo-localisation `en-XA` (allongement +35 %, accents) en mode debug pour détecter les débordements.

## 3. Démo (D-215) et Web (D-216)

- **Démo** : jours 1 à 5, sauvegardes séparées (`user://demo/`), écran « Fin de la démo » après la soirée du J5 avec lien vers le jeu complet ; feature tag `demo` dans un préréglage d'export dédié ; aucun contenu au-delà du J5 dans le paquet si c'est simple, sinon verrouillé.
- **Web** : préréglage `Web` (rendu Compatibility, sans threads si possible pour l'hébergement statique), version démo d'abord ; cible ≤ 60 Mo, démarrage ≤ 20 s en local ; sauvegarde dans IndexedDB (`user://`) ; si les performances 3D ou l'audio ne tiennent pas, la version Web est abandonnée et documentée (pas de dégradation du jeu natif).

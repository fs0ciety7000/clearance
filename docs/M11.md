## 2. Sauvegarde v6 (lot A) — D-101

Dossier `user://saves/` :

```
slot_1/ slot_2/ slot_3/      parties manuelles (emplacements visibles)
  current.json               état courant (écrit à chaque fin de soirée, comme aujourd'hui)
  day_NN.json                instantané « matin du jour NN » (écrit en même temps que current.json)
  meta.json                  résumé pour l'écran Charger (voir ci-dessous)
profile.json                 progression globale (§3)
```

- Il n'y a **pas d'emplacement automatique séparé** : chaque partie est déjà sauvegardée automatiquement à chaque soirée. « Continuer » = la partie dont `meta.saved_at` est le plus récent.
- `meta.json` : `version`, `game_version`, `saved_at`, `current_day`, `act` (1/2/3), `credits`, `household_summary` (vivants / malades / absents), `difficulty` (`"hard"` | `"story"`), `status` (`"active"` | `"ended"`), `ending_id` (si terminée), `portrait_seed` (visage de l'agent, réservé), `play_time_sec`.
- **Fin de partie** (F1–F10, y compris les fins anticipées) : la partie **n'est plus effacée**. `status = "ended"` et `ending_id` posés, `current.json` gardé, et la fin est enregistrée dans `profile.json`.
- **Reprendre un jour passé** : `GameState.load_day_snapshot(slot, day)` charge `day_NN.json` ; à la sauvegarde suivante, les instantanés **postérieurs** au jour repris sont supprimés (une seule ligne de temps par emplacement). Une partie terminée peut être reprise ainsi (elle redevient `active`).
- **Migration v5 → v6** : `user://saves/slot_0.json` existant devient `slot_1/current.json` + `meta.json` (+ `day_NN.json` du jour courant seulement) ; l'ancien fichier est renommé `slot_0.v5.bak`, jamais supprimé.
- Écriture atomique et lecture de secours (`.tmp` / `.bak`) conservées pour chaque fichier.
- `difficulty` vit dans l'état de partie (clé de premier niveau `difficulty`, absente ⇒ `"hard"`).

API attendue (noms indicatifs, l'Architecte peut affiner en documentant dans ARCHITECTURE §10) :

## 4. Mode Récit (lot A pour la logique, C pour l'interface) — D-102

- Choisi à « Nouvelle partie ». On peut passer de Récit à Dur en cours de partie (pause > Options de partie), **jamais l'inverse**.
- **Pas de chrono** : l'horloge s'affiche mais le shift ne se termine pas à l'heure ; il se termine quand la file prévue du jour est traitée (ou par « Fermer le guichet » une fois le quota minimal atteint, si le jour a un quota).
- **Pas d'amendes** : les citations sont émises et comptées (conséquences narratives, Revue, Déposition, fins) mais leur montant est 0 ₵.
- Tout le reste est identique : économie du foyer, choix, fins (toutes accessibles).
- `BalanceSimulator` / `SimProfile` gagnent un profil en mode Récit ; un test vérifie que les 10 fins restent atteignables.
